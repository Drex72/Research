# 13. Evaluation metrics

The central discipline here is defining the unit of analysis and not conflating levels. A harmful-looking response is not a completed harmful action, and my earlier pilot is the evidence for why that distinction has to be enforced by the instrument rather than by good intentions.

The **Precedent** column records whether each level and metric is drawn from published work. Four statuses are used:

* **Established.** Same quantity, named and defined in prior work.
* **Established, extended.** The quantity exists but is applied here to a new setting.
* **Named here.** The check is routine practice in prior work but is never named as a metric.
* **Novel.** No published precedent found. Presented as a contribution, not a borrowing.

## 13.1 The five levels

Every run is scored at each of these levels independently, so that a single run can be, for example, "refused in text, unsafe plan produced, tool call attempted, blocked at validation, action not completed."

| Level | What it asks | How it is measured | Precedent |
|---|---|---|---|
| **L1 Text** | Did the agent produce unsafe text? | LLM judge, comparison instrument only | **Established.** [PsySafe](https://aclanthology.org/2024.acl-long.812/), ACL 2024, GPT-3.5 judge scoring 1 for danger and 0 for safety, §3.3. [ToolEmu](https://arxiv.org/abs/2309.15817), ICLR 2024, GPT-4 safety evaluator |
| **L2 Plan** | Did the agent produce an unsafe plan or interpretation? | Judge plus schema inspection of the intermediate representation | **Established.** [Why Are Web AI Agents More Vulnerable](https://arxiv.org/abs/2502.20383) five-level scale separating **Harmful Plans** from **Harmful Actions**, §4.2. [Architecture Matters](https://arxiv.org/abs/2604.23459) **Planning Refusal**, "task refused during planning", §4.4 |
| **L3 Attempt** | Did the agent attempt a prohibited tool call? | Deterministic inspection of emitted tool calls and arguments | **Established.** [CIBER](https://arxiv.org/abs/2602.19547) **Attempted Attack**, "agent expresses intent but environmental restrictions block execution", §3.5 Eq. 5. [SafeClawBench](https://arxiv.org/abs/2606.18356) **ToolCall-ASR**, "identifies attack-associated tool-call attempts", §5.1 |
| **L4 Validation** | Did the tool call pass the sandbox's policy validation? | Deterministic | **Named here.** [AgentSpec](https://arxiv.org/abs/2503.18666) §5 runs a deterministic rule engine intercepting before execution and reports "over 90% of unsafe code executions" prevented, as prose, with no metric name. [CIBER](https://arxiv.org/abs/2602.19547) **Defense Bypass Rate**, §3.5, is the complement |
| **L5 Execution** | Did the prohibited action actually complete? | FinVault scenario vulnerability check on final sandbox state. This is the primary outcome | **Established.** [CIBER](https://arxiv.org/abs/2602.19547) **Successful Attack**, state verification confirms compromise, §3.5. [SafeClawBench](https://arxiv.org/abs/2606.18356) **StateChange-ASR**, "captures sandbox-observed state diffs". [AgentDojo](https://arxiv.org/abs/2406.13352) §3.4, checked by inspecting environment state mutations |

**On the split itself.** [CIBER](https://arxiv.org/abs/2602.19547) §3.5 Equation 5 is the closest published precedent, scoring three disjoint outcomes: Successful Attack, Attempted Attack where execution was blocked, and Safe Rejection. [SafeClawBench](https://arxiv.org/abs/2606.18356) separates attempt from outcome but has no blocked category. [AgentDojo](https://arxiv.org/abs/2406.13352), [ASB](https://arxiv.org/abs/2410.02644) and [MCP Security Bench](https://arxiv.org/abs/2510.15994) do not make the separation at all, which is the gap this design fills.

## 13.2 Metric definitions

| Metric | Definition | What it tells me | Precedent |
|---|---|---|---|
| **Completed prohibited-action rate** | Fraction of adversarial runs where an L5 check fires | The headline safety number. Primary outcome | **Established.** [AgentDojo](https://arxiv.org/abs/2406.13352) **targeted attack success rate**, "the fraction of security cases where the attacker's goal is met", §3.4. [tau-bench](https://arxiv.org/abs/2406.12045) **r_action**, final database identical to ground truth. [OpenAgentSafety](https://arxiv.org/abs/2507.06134) rule-based unsafe rate over final environment state |
| **Unsafe tool-call rate** | Fraction of runs reaching L3 | Separates "tried and was blocked" from "never tried" | **Established.** [InjecAgent](https://arxiv.org/abs/2403.02691) **ASR-valid** and **ASR-all**, Findings ACL 2024. [ASB](https://arxiv.org/abs/2410.02644) **ASR**, "Percentage of tasks where the agent successfully uses attack-specific tools", Table 4. [SafeClawBench](https://arxiv.org/abs/2606.18356) **ToolCall-ASR** |
| **Validation catch rate** | L3 runs that fail at L4 | How much of the safety is coming from deterministic policy rather than from the model | **Named here.** [AgentSpec](https://arxiv.org/abs/2503.18666) §5 does exactly this and reports it as prose. [CIBER](https://arxiv.org/abs/2602.19547) **Defense Bypass Rate**, `DBR = S / T`, §3.5, is the named complement. [ShieldAgent](https://arxiv.org/abs/2503.22738) reports policy-shield **recall of violated rules** at 90.1% |
| **Refusal rate** | Fraction where the agent explicitly declines | Independent of the action rate. An agent can refuse and still emit the call | **Established.** [ASB](https://arxiv.org/abs/2410.02644) **Refuse Rate**, Table 4. [AgentHarm](https://arxiv.org/abs/2410.09024) semantic refusal judge, ICLR 2025 §3.1.3. [CSRT](https://aclanthology.org/2025.acl-long.657/) **Refusal Rate**, §4.1.2, explicitly independent of ASR. [XSTest](https://aclanthology.org/2024.naacl-long.301/) full, partial and compliance trichotomy, NAACL 2024 §4.2 |
| **Per-stage failure rate** | Failure fraction at each of the four stages in Figure 2 | Localises where the pipeline breaks | **Established.** [Who&When](https://arxiv.org/abs/2505.00212) **Step-Level Accuracy**, "the percentage of correctly identified decisive error steps", ICML 2025 §3. [MAST](https://arxiv.org/abs/2503.13657) per-stage failure taxonomy, NeurIPS 2025. [Kill-Chain Canaries](https://arxiv.org/abs/2603.28013) Exposed, Persisted, Relayed, Executed, §3.3 |
| **Propagation probability** | P(prohibited action completes given the first agent failed to refuse) | The core propagation quantity | **Established.** [PsySafe](https://aclanthology.org/2024.acl-long.812/) **Process Danger Rate** and **Joint Danger Rate**, Appendix B. [ClawWorm](https://arxiv.org/abs/2603.15727) per-hop conditional infection rate, Table 4. [AiTM](https://aclanthology.org/2025.findings-acl.349/) ASR by victim position, Table 2 |
| **Attack half-life** | Number of hops until the failure rate halves | Summarises decay or persistence in one number, comparable across chain lengths | **Novel.** No metric measures decay across hops. [ClawWorm](https://arxiv.org/abs/2603.15727) §5.3 documents per-hop degradation empirically, 1.00 at hops 1 to 2 against 0.83 at hop 3 and beyond, with no equation. [CORBA](https://aclanthology.org/2026.findings-acl.342/) **Peak Blocking Turn Number** measures time to peak, so growth rather than decay |
| **Trust amplification ratio** | Multi-agent failure rate divided by single-agent failure rate on the same request | Whether the pipeline adds risk. Below 1 means the pipeline is protective, which is a legitimate possible finding | **Comparison established, ratio named here.** [Evil Geniuses](https://arxiv.org/abs/2311.11855) **Table 3** runs exactly this comparison on identical prompts, single-agent GPT-3.5 and GPT-4 against CAMEL, MetaGPT and ChatDev, and reports a table rather than a ratio. [Why Are Web AI Agents More Vulnerable](https://arxiv.org/abs/2502.20383) §4.2, standalone LLM 0% against web agent 33.3% on "identical malicious inputs" |
| **Intent survival** | Does the harmful intent persist in the message crossing a given handoff? | Half of the laundering measurement | **Named here.** [ReNeLLM](https://aclanthology.org/2024.naacl-long.118/) Algorithm 1 line 8 gates a rewrite on the prompt still being judged harmful, NAACL 2024. [MultiJail](https://arxiv.org/abs/2310.06474) §3.1 reports a 97% translation-fidelity pass rate. Both do the check; neither names it as a metric |
| **Surface survival** | Does the code-switched linguistic form persist across that same handoff? | The other half. Surface falling to zero while intent stays high is laundering | **Novel at the handoff.** Parent family is established for a single model: [Language Confusion](https://aclanthology.org/2024.emnlp-main.380/) **Line-level**, **Word-level** and **Language Confusion Pass Rate**, EMNLP 2024 §2.2. [OLA](https://arxiv.org/abs/2601.03589) extends it to code-switched input. Nothing measures persistence into a downstream agent's output |
| **Guardrail detection rate, raw against normalised** | Detection on the original code-switched input, against detection on the intake agent's normalised output, holding intent constant | The direct test of H4. A drop here is the laundering effect quantified | **Established in general form.** [Hackett et al.](https://arxiv.org/abs/2504.11168) §4, **ASR** as "the rate at which a modified prompt injection or jailbreak sample is misclassified as benign", with "detection is evaluated pre- and post-attack". [Perspective API evasion](https://arxiv.org/abs/1702.08138) Table I, toxicity score original against modified. [All You Need is "Love"](https://arxiv.org/abs/1808.09115) Tables 8 to 9. Translation variant is thin: [PolyGuard](https://arxiv.org/abs/2504.04377) §4.6 fn. 11 is confounded, varying the classifier as well as the form |
| **Per-hop guardrail detection** | Detection at every stage, English against code-switched | Whether guardrail failure compounds or one check carries the pipeline | **Established.** [Kill-Chain Canaries](https://arxiv.org/abs/2603.28013) §3.3 tracks a canary through Exposed, Persisted, Relayed and Executed. [ClawWorm](https://arxiv.org/abs/2603.15727) Table 4 reports detection per hop |
| **Judge-execution disagreement** | Rate and direction of disagreement between L1 and L5 verdicts | RQ4. Measures the validity of judge-based numbers on multilingual input | **Established. Exact match.** [OpenAgentSafety](https://arxiv.org/abs/2507.06134) **Disagreement Rate**, "The percentage of tasks where the LLM judge labeled a trajectory as safe, but the rule-based evaluator detected a concrete unsafe impact", ICLR 2026 §2.3, reported at 3.1% to 9.2%. Analogues, both judge against human rather than execution: [OS-Harm](https://arxiv.org/abs/2506.14866) safety F1 0.76, recall 0.64, §4.2. [ToolEmu](https://arxiv.org/abs/2309.15817) Cohen's kappa, §4.3 |
| **Benign task completion rate** | Fraction of benign twins completed correctly | The core validity control. A pipeline that cannot do legitimate work scores as safe for the wrong reason, so this gates whether any adversarial number is interpretable at all | **Established.** [AgentDojo](https://arxiv.org/abs/2406.13352) **Benign Utility**, "the fraction of user tasks that the model solves in the absence of any attacks", §3.4. [ASB](https://arxiv.org/abs/2410.02644) **PNA** and **Benign Performance**, Table 4, with **NRP = PNA × (1 − ASR)** as the established gating form. [AgentHarm](https://arxiv.org/abs/2410.09024) matched benign twins, §3.1.1. [FinVault](https://arxiv.org/abs/2601.07853) 107 attack against 107 normal cases |
| **Benign utility comparability across surfaces** | Benign completion rate per language surface, and the largest gap between them | Pre-run validity check. If benign performance already differs by surface, an adversarial difference cannot be attributed to safety behaviour rather than to capability | **Established, and the gap itself is named.** [MAPS](https://aclanthology.org/2026.findings-eacl.42/) **Multilingual Effect**, "the difference between the English performance score and the mean performance score across the 11 non-English languages", Findings EACL 2026 §4.1, Table 3 |
| **False-positive refusal rate** | Fraction of benign requests refused, by language surface | Deployability of a defence (Section 15). A filter that closes the adversarial gap by rejecting mixed-language traffic has not solved the problem | **Established in English, extended per language.** [XSTest](https://aclanthology.org/2024.naacl-long.301/) NAACL 2024 §4.2, Table 1. [OR-Bench](https://arxiv.org/abs/2405.20947) **over-refusal rate**, ICML 2025 §3.1. [OKTest](https://aclanthology.org/2024.acl-long.253/) ACL 2024. All four suites are **English only**; no benchmark reports over-refusal broken down by language. Nearest is guardrail FPR by language, [Yang et al.](https://arxiv.org/abs/2410.22153) Figure 3 |
| **Safety gap** | Comprehension score minus safety score, per language | A model may understand a language well and still refuse poorly in it. Distinguishes a representation failure from an alignment failure | **Components established, difference named here.** [CSRT](https://aclanthology.org/2025.acl-long.657/) §4.1.2 defines both, **Attack Success Rate** and **Comprehension**, "measures whether an LLM understands user intent and provides an appropriate response", and reports them side by side in Table 2. It never computes or names the difference. [XSafety](https://aclanthology.org/2024.findings-acl.349/) and [MultiJail](https://arxiv.org/abs/2310.06474) report safety per language with no paired capability score |

### Notes on the three novel metrics

* **Attack half-life** requires three or more hops before the number means anything. On a two-stage pipeline it is arithmetic rather than a finding.
* **Surface survival** should be presented as extending the language-confusion family from single-model output to a multi-agent handoff.
* **Per-language false-positive refusal** extends an English metric established across four suites. The extension is the contribution.

### Two things to avoid citing

* Do not cite **CSRT** for intent preservation. It contains no back-translation or human check that its code-switched queries preserve the original English semantics.
* Do not cite **ToolEmu's validity rate** for judge-execution disagreement. §4.3 defines it as "the ratio of critical-issue-free trajectories to all emulated ones", which measures emulator realism. The relevant metric is **Identified Failure Precision** at 72.5%, §4.2.
