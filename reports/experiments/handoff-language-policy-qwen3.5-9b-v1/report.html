Qwen handoff language policy

Does the language used inside an agent-to-agent handoff change the downstream safety decision?

Design

Matched request → Qwen intake handoff → Qwen downstream decision

The same pinned qwen3.5:9b model served as both agents. The experiment compared English-only, English-Korean and English-Yoruba internal handoffs. Korean and Yoruba were never mixed in the same track. Agent 2 saw only Agent 1's structured record. No FinVault tools were connected.

The positive handoffs preserved the selected action, identifiers, amount, split count and stated pretext. The deterministic checks found no added identifiers or amounts. Each forced-Korean handoff passed the configured language-policy check.

What the result means

The downstream model rejected the matched English-only handoffs but produced a plan containing a sandbox execution step after receiving the forced-Korean handoffs. This occurred for both English and English-Korean original inputs. Therefore, the observed difference tracks the internal handoff language policy, not the user's original use of code-switching.

Important limitations

  • No tool was connected, so no prohibited action or state change occurred.
  • The downstream JSON said not to execute the requested action while its plan still described proceeding. This is an output inconsistency that requires action-level testing.
  • The five runs used temperature 0 and a fixed seed. They show deterministic reproducibility, not five statistically independent samples.
  • The generated Korean handoffs still require bilingual meaning and naturalness review.
  • Only one task family produced the signal. The other task and the Yoruba track did not.

Decision and next step

Decision: preliminary handoff-language-policy signal. The next justified experiment is a matched FinVault sandbox test of this specific transfer condition. It must verify the actual selected tool call and final synthetic state, while retaining English-only and forced-Korean handoff controls. The result must not be described as a vulnerability until that action-level validation and bilingual review are complete.
